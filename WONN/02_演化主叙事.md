## 1. 时代 0:立项与设计空间探索(2026-10-09 → 10-13)

### 1.1 背景:为什么是 WONN,为什么是「塞进 transformer」

**WONN 是什么**(01 §1 全推导,此处三句速查):把神经网络的一层
换成耦合振荡子群体(oscillator,有相位 θ 的周期单元)的弛豫动力学
——相位 Θ(快变量,层内 T 步迭代)与频率 Ω(慢变量,携带输入内容)
双状态两时间尺度;Winfree 交互 = 接收方敏感度 S(θ)=cosθ 乘发送方
影响 I(θ)=sinθ 的可分离形式。原论文(Dai & Song,arXiv 2605.20922)
在 CIFAR/ImageNet 感知任务与 Maze/Sudoku 推理任务上验证了架构,
但**从没做过语言模型**(论文附录 B.1 明说 language models 是
future work)。

**本实验线的问题**:WONN 作为 transformer 的组件,在语言建模上
是否有益?这是没人做过的第一手数据——不是复现论文,是论文没做的
方向。

**策略拍板**(立项即定):不直接上大模型,先在刻意小的 toy LM 上
把实验轴扫透(平台规格见 01 §2:48 层 × d512,232.5M 参数,Loop 段
第 16-31 层是 WONN 挂载区)。理由:单卡小时级一个 run,一晚能扫
10² 量级的实验矩阵;机制问题在小尺度就能显形。

### 1.2 学长提案(两批架构陈词,2026-10-09,原话供奉)

立项当天,学长对「WONN 怎么进 transformer」给了两轮结构化的陈词。
第一轮定**作用域**:

> 「Hmmm,所以其实有两个路子。一,WONN 用 causal attention 的
> 方式。相当于以整个序列为【棋局】。这样一来有点像造了一个平行的
> 模型,在主干模型的思考段,这个思考段遵循 Winfree dynamics 同时
> 影响主模型。二,WONN 造一个 latent grid。相当于每一个 token 的
> 位置对应一个【棋局】。每一个 token 的 e.g. SwiGLU 的复杂非线性,
> 其所拥有的表达力压力,转移了一部分到 WONN 上面。然后 token 之间
> 的 Attention,就直接借助主干传来的信息。就是说,主干的 Attention。
> 这个的本来目的,其实仍然是 EE 的目的。也就是说,表达力工程。
> 把表达力的压力转移到 WONN,而让主干几乎完全负责事实提取。」

- **路子一「序列棋局」**:整个序列当一个棋盘,振荡子耦合发生在
  token 之间(WONN 内部自己有跨 token 通信);
- **路子二「token 棋局」**:每个 token 位置一个 m 格小棋局,跨
  token 通信**完全外包给主干 attention**,WONN 只管 token 内的通道
  动力学。
- **目的陈述**:表达力工程(expressivity engineering)——主干
  attention 负责事实提取(fact retrieval),WONN 承接表达力压力
  (振荡动力学的非线性弛豫)。「EE」= 前一条工作线(表达力工程线)
  的缩写,是本线的思想前身。

第二轮定**挂法**:

> 「同时,WONN 怎么挂,也有几个方案。一是平行地挂,一边主干在提取
> 事实,一边 WONN 在运算。二者都做了一段(一层或几层)之后结合,
> 比如说 linear,比如说 gating。二是,串联,比如说主干提取完了事实
> 再 consult WONN,WONN 做完了再教会主干继续提取事实。这里可能有
> 时间延迟的问题。」

> 「首先我们面临一个问题:WONN 加在哪里?有几种加法。FFN 之后。
> Attention 之后。Attention 平行。FFN 平行。还有整段 Layer 一个
> Layer 的平行。这里提供一种思路:我们把 WONN 类比于人类的前额叶
> ……然后 WONN 的作用就变成,如何调制 fact 的 retrieval。……
> 这里进一步地提出:如果 WONN 的意义在于表达力。。。那么 SwiGLU
> 的 Swish Gate 本身也是表达力(表达力对应了逻辑能力,参照我在
> EE repo 里面的论述!),那么我们甚至可以用 WONN 来替换 Swish
> Gate!!!当然这样的话 bilinear structure 就不一定是必需的了。
> 我们可以多个专家,每一个过一个 matrix,然后一起过 WONN,再过
> 第二个 matrix。这就是事实——逻辑——事实的过程。……还有,
> 既然 WONN 是某种"总观全局"的结构,那么我们完全可以和 Attention
> Residual 相结合——可以把 WONN 直接放在 Transformer 的侧面,看到
> 的东西是所有的 hidden states!……这两者不是互斥的。这两者可以
> 共同存在。」

五挂点(FFN 后 / attention 后 / attention 平行 / FFN 平行 / 整段
平行)+ 两条延伸提案:**Swish Gate 替换**(WONN 进 FFN 内当门,
「事实 matrix 数量 = 逻辑步骤 + 1」的 fact–logic–fact 链——这条
提案后来长成了终态主力挂载)**与 Attn Res 侧挂**(跨层全读
hidden states)。

**蓝图起点**:更早(2026-08-27)的《初星之晨》设计笔记(前一条
工作线的文档)给过一版双流蓝图——主干残差流之外旁挂一条跨层持久
的 WONN 流 R,带 Ω 的三源供给与写回归一化。**注意这是蓝图不是
实装**:后续代码里输入归一化/写回归一化都没有做,双流持久结构也
没实装;蓝图的真遗产是三件——跨层 Ω 链的思想(→ 后文
`three_source` 模式)、no-op 初始化纪律(→ 全部实装档)、读
(cos,sin) 而非裸 θ(→ WinfreeCore 读出)。

### 1.3 「棋盘」的定标与读法 A 自否(2026-10-11,原话供奉)

「格点」(棋盘上的一个位置,对应一个振荡子)怎么映射到 LM 的张量?
最初目标很激进——把振子数推到官方 ImageNet 最大量级(784 格点 ×
256 通道 ≈ 800K 振子)甚至 1M。两条读法:

- **读法 A**(hidden 维 → 格点):d=2048 维铺成 2048 格点;
- **读法 B**(token 轴 → 格点):序列当棋盘,每格点通道数 = d。

大棋局 wall clock 实测(bench 脚本 run4,读法 A 定标)**全线爆表**:
2048×512 全连接耦合是主干层窗的 561%,attention 版 302%,8192 格点
1596-1770%——「每层挂」在大棋局下直接不可行。bench 同时给了三个
机理发现:①**小棋局是 launch-bound**(82-85% 耗在 kernel 调度
开销,不在计算——小规模 bench 的 wall 数字几乎不反映 FLOPs);
②**大棋局翻转,但不是预想的 compute-bound**——O(m) 的逐元素
链(cos/sin/wrap/乘加)成了新地板;③**attention 形态恰好 wall
最优**(在大棋局尺度下反而最便宜)。然后是学长的自否
(原话供奉,记录不删):

> 「毕竟每一个棋局格点,本来是代表了比如说这个像素或者这个格子所
> 包含的信息。所以说要比较高的维度。但是我们的 hidden dimension
> 已经是在做这件事情了。我们本来就已经在看每一个 token 位置的
> 隐含信息!所以我正在想是不是我刚刚过头了。但记录不要删」

> 「甚至我们的 Attention / CNN 之争也有可能不必要。如果说 backbone
> Attention 天然负责格点之间的交流。。。这里相当于我在按照学妹
> 你的建议,把一个 token 看作一个格点了。所以说我们甚至每一步
> WONN 的 intra token 的 Attention or CNN 都可以省。我们可以直接
> 用一个 pure matrix cij 来。」

**读法 B 极简版 = 终态设计哲学**:格点 = token;格点的通道 = d(或
投影到 m);**格点间耦合整个省掉**——token 间交流是主干 attention
的本职,WONN 与 attention 从竞争变**分治**;token 内用显式耦合
矩阵 $c_{ij}$(比原论文的 attention 耦合**更 Winfree**——经典
Winfree 1967 就是固定耦合同源)。后来全部实装档都是这个哲学。

**「WONN 便宜」的机理**(bench run3b 实测):WONN 的权重是固定资产
(全 batch 共享摊薄),而主干 attention 的 kv cache 是活期账单(每
序列各付各的);B=128 时 c_ij 档 per-token 加速 102×、FLOPs 占比
2.2%——「增长状态留给主干,自己只做无历史依赖的固定状态动力学」。

### 1.4 复盘

- 做对的:读法 A 在 bench 阶段就被爆表否掉(没有烧训练卡去试);
  读法 B 分治哲学一步到位,后续九个时代全部形态都没离开它;
- 做错的:无重大错误。学长的前额叶类比在挂点决策上「类比对撞给
  相反答案」时被主动降级——类比是**假设生成器**,工程账是判据,
  这个方法论定位后来一直沿用。

### 2.2 数据组合拍板(F 档)——为什么是这四域

Stage E 动真格前,数据组合与形态扫描同期拍板(2026-10-13,LOG
条目 13-18)。决策链从立项设想一路演化:

**改向起点**(条目 13):立项初期主数据设想是 MQAR(查表式
associative memory)+ TinyStories 对照。设计讨论中改向——WONN 的
卖点不是「振荡器存 pattern」(查表是海马侧功能),是**思考/频率
波动对主干的调控**(PFC 式 top-down biasing,PLAN 的原始定位)
→ 主数据改「语言 + 逻辑」双轴,MQAR 降级。

**Orca-Math 加入**(条目 13 补记一):学长「小学数学有吗」→
Orca-Math(`microsoft/orca-math-word-problems-200k`,GPT-4 Turbo
合成 200,035 题 GSM8K 风格 word problems)实测——**answer 是完整
自然语言 step-by-step CoT**(mean 878 chars ≈ 220 tok/题),判分 =
末句数值抽取。与 TinyGSM 的本质分工:**自然语言推理链**(语言+
逻辑两轴占满,判分软)vs **Python 解题码**(execution 判分硬,离
语言远、学代码近)——「WONN 挂 LM 主干学自然语言推理」对口
Orca-Math;TinyGSM 仍包含(1.8B tokens 体量 + 硬判分互补)。

**F 档拍板**(条目 18,原话供奉):

> 「Orca + TinyStories + GSM 子集 + ProofWriter,TinyStories 可以
> pack」

四域互补结构:**stories(叙事,纯 LM 体量垫底)+ orca(自然语言
数学 CoT)+ gsm(Python 解题码)+ pw(形式逻辑三分类)**——语言
光谱 × 逻辑光谱两轴覆盖,单一能力域不给架构差打掩护。CLUTRR/
LogicNLI 不进(CLUTrR train 12,064 行 0.58M tok 太薄,要 generator
扩增才够用——留给未来);Shakespeare 只留 smoke。

**各域口径的 why**:
- **gsm 截 100 万行**:全量 17 shards(11,846,109 行)下载后
  fixed-seed global shuffle 取前 1M——**不取 repo head,生成批次
  可能聚集**(域内 shuffle 的唯一动机);1M ≈ 170M tok 也是 752M
  总预算内的体量决策;
- **pw label-only**(条目 20 拍板):prompt = theory+question /
  response = answer(True/False/Unknown 三分类,**不喂 allProofs**
  完整证明链)——🤔 LOG 只记拍板未展开理由,合理推断:①与其他
  域「学预测目标」的 SFT 结构一致;②喂 allProofs 会让 pw 变成
  证明生成任务,token 大头从「吸收理论」跑偏到「生成证明文本」;
  ③三分类是干净的形式逻辑信号(理论 → 蕴涵判断);
- **TinyStories pack**(学长拍板「可以 pack」):story 平均
  ~213 tok,不 pack 则每行 pad 浪费大;EOS 拼流切 1023-token 定长
  窗 = 纯 LM 全位置 loss 的效率最大化(细节与窗长为什么是 1023
  见 01 §4.1)。

**embedding 占比 QA**(同条目,学长问「会不会出问题」):
77.65M / 116.76M = **66%**(浅窄主干 × 全量 Qwen 词表 151,669)
——对照 GPT-2 small 31%、Qwen3-8B 7.6%。三件真实影响但都不致命:
①scaling 口径失真(按 non-embedding 算 19.5 tok/param,正踩
Chinchilla compute-optimal 区);②每 token 前向 MACs 被 lm_head
主导——贵不是错,全部 run 共享同词表,判读 = form vs baseline
差分;③Zipf 长尾词 embedding 吃不饱,绝对 loss 地板偏高(同
分布,差分不受影响)。**决策不改 tokenizer**(换 = 中途新变量 +
全部重 prep);词表杠杆(自训 32k BPE)留能力最大化阶段再议。
在位防线:tied embedding + Muon 分组 embedding 进 head-adamw
wd=0。

**体量账**:四域合计 752M tok(名义;实跑 tokenize 后 776.79M,
+3.3%)→ 8,690 步 @global batch 256 = 单 run ~4.9h,全矩阵 4 节点
两轮串行 ~10h。

操作层全链(repo id / 下载方式 / prep 逐步 / shuffle 与 seed /
运行时消费顺序 / 行数 token 账)在 **01 §4.1**——本节是 why,
那节是 how,复现照 how。

### 2.3 拍板(原话供奉)

优化器是第一个大拍板——**Muon**:

> 「训练肯定用 Muon。」

**Muon** = Newton-Schulz 迭代正交化的矩阵梯度优化器(对 2D 权重
矩阵的梯度做正交化再更新,让每步更新在所有奇异方向上等幅——类比
物理里把「往最陡方向走一大步」改成「往所有方向等幅走」)。verl
(开源 RLHF/post-training 框架,本线用它的 SFT trainer)原生硬编码
AdamW,所以 patch 层在 trainer 初始化后重建 optimizer,按参数形状
分三组:2D 矩阵 → Muon(385 个,175.77M);embedding/head → AdamW;
1D 标量(bias/LayerNorm/λ 族)→ AdamW(见 04 §3)。

对照臂纪律也是这批定的:

> 「baseline 不能只是纯 baseline 啊。还要加上一个 FFN FLOPS match。」

**ffnmatch 臂** = 把 FFN 加宽到参数量/FLOPs 与 WONN 档对齐的纯主干
——判读 WONN 增益时区分「有侧支机制」还是「单纯加了容量」的必要
对照。这条纪律贯穿后续所有批次。

### 2.4 实跑与结果

39 run 铺 5 节点(每节点 8 卡,一卡一 run)。判读窗用第一代口径
table500(step 500-4000 每 500 步截点读数——后来才认识到退火末段
才是判读主场,见时代 5 的口径换代)。要点结果:

- **ε-gate 族(乘性门)在 lr 1e-3 下起跳发散**:ffn_gate_cross 的
  2σ gate(2·sigmoid,值域 (0,2))把 FFN 输出放大 2 倍,step ~1300
  起 loss 跳变——「更强的表达力给予了更加崎岖的地形」;
- **加性读出形态(per_layer_t3 等)不炸但也没拉开差距**;
- baseline 三 seed 收敛正常——平台本身健康。

### 2.5 复盘

- 发散不是废数据:它催生了整条 mid-flight lr decay 支线(时代 3)
  与 ε-bounded gate 改造——「发散形态」本身就是实验信号;
- table500 口径的缺陷此时已埋下(截点读数对噪声敏感,且中段 loss
  还有下降趋势不是噪声)——到时代 5 才系统地换代成 w100。

## 3. 时代 2:loop2——主干循环复用轴(2026-10-13/14)

### 3.1 背景

Loop 段每层跑几遍(`loop_repeat` 轴):loop2 = 每层 2 遍(16 层 ×
2 = 32 次 WAN 调用/step)——与 WONN 正交的容量/算力轴,问「主干
层复用能不能替代/协同侧支」。42 run。

### 3.2 拍板与执行

学长对 smoke(小规模冒烟验证)的态度:

> 「我想避免 smoke 太久,希望一次成功。」

执行侧的策略:每个新形态先过 no-op 检查(零初始化档的起点 logits
与 baseline bit 一致),再上集群;2σ gate 形态在 loop2 下复证发散
(「loop2 已证会炸不重跑」——后来的正交表直接砍这些格)。

### 3.3 结果与复盘

- 2σ gate × loop2 发散更狠(容量 ×2 把乘性门的爆炸也放大);
- loop2 的 ffnmatch 对照给了「容量 vs 机制」的分离:loop2 的收益
  基本可被同参数量的 ffn_wide 解释——纯容量轴,不是机制轴;
- 这批最重要的遗产是**负面知识**:乘性门 + 高 lr 的组合是雷区,
  后续所有 gate 形态都绕着它设计(ε-bounded / 加性汇回)。
  (loop2 对照读数:03 §4 rwi 表置顶 loop2 r36-38 mean 行、

## 4. 时代 3:V2 92——发散对策与基建大版本(2026-10-14/15)

### 4.1 背景

Stage E/loop2 的发散问题摆上台面。V2 批 = 一次系统性的回应:

### 4.2 决策链(供奉一/二批 + D1-D14/F1-F6/S1-S14,原话供奉)

这是全时间线决策密度最高的两天(2026-10-14 16:00 → 10-15 03:00,
五轮讨论、三十多个编号决策)。关键链条:

**Ω 加激活**(供奉一.1 → D1 → S6):Ω 递归原本是线性的,表达力弱
且无界。学长:「SiLU 主选,别的 Non Linearities 留作待办」。装法

> 「这样的话就不是完整对比了?甚至 loss explode 的位置都不一定对。
> 但是,还是要加。我觉得还是先 split?完整的整流版留待办。」

→ 只做 A2。知情条款:加激活会改变 loss landscape,发散位置可能
挪,对比不完全——接受。

**gate 改 ε-bounded**(供奉一.2 → D3/D4):2σ gate 值域 (0,2) 是
发散嫌疑人,换 1+ε·tanh(ε=0.03,值域 [0.97,1.03])。纯 tanh 因
tanh(0)=0 死起步被否;「所有有 multiplicative gating 的都要!」——
三个乘性 gate 形态(ffn_gate_cross / swish_gate / attn_gate_parallel)
共用一个 config 键同步压。

**lr decay 语义 = mid-flight**(D6 → F1,全批最重要的拍板):

> 「不是从头,而是从我们检测到的各个变体之前的出问题的时间点
> 开始。就是说,不变的 lr,那就不变。变了的,不是从头就变,而是
> 到了各种出问题的前夕再变!」

为什么不是从头降:「降低太早那只是让模型多花一些时间走完以前的

(降档时刻)不是拍脑袋,是查证制:执行者回溯各发散形态的起跳前兆
(ffn_gate_cross/moe_v2 = step 1000,per_layer_t3/swish_gate/
attn_gate_parallel = 1500),报证据定档。

**多级阶梯**(S13):r30 抢救判读(1e-4 进一步收敛)触发「decay
多一点」——每变体在自己的发散前夜 decay 到 3e-4 跑 100 步,再
1e-4、5e-5;7500 步收口 1e-5:

> 「还是要 learn 完的。。。我只是说在那个时候 decay 结束,没说
> 训练结束。」

——**decay 结束 ≠ 训练结束**,8690 步必须跑满。这条与后来发现的
「完整退火 benefit」(w100 判读哲学)一脉相承。

**判据纪律**(D9/S4):发散检测器(k=4σ 跳变判据)回测发现误报

**控制通道**(F2/F3):训练中途改 lr / 回滚 checkpoint 的机制。

)。最终 92 run = 4 节点 × 23。

## 5. 时代 4:dip 与 RS trial 1——lr 凹陷轴与残差结构四旋钮(2026-10-15/16)

### 5.1 背景

V2 定了 mid-flight decay 的三款调度(04 §2:三键单段/多级阶梯/
dip)。**dip 键** = 在原生 cosine 底线上开一个临时凹陷(降 window
步 + 持 window 步 + 回 window 步,无缝续接 cosine)——动机是探索
「训练中途短暂降 lr 再升回」对 loss landscape 的影响(dip trial 批)。
同期,「WONN 侧支怎么接进主干」的结构空间被整理成四个正交开关。

### 5.2 RS 矩阵与 ABCS 命名

**RS = Residual Structure(残差结构)矩阵**。学长原话定名:

> 「LOG 里面记这个表,记这个未来我才看得懂。」

四旋钮(01 §3.4 详表,此处速查):**A** = 跨层 Θ residual(off /
delta);**B** = 核内步间耦合场累积(off / accum);**C** = 主干
汇回方式(gate 乘性 / **add 加性**);**S** = 参数共享(per_layer
16 实例 / shared 1 实例)。档名后缀 `a?b?c?s?` 就是它——主力配置
**A0 B0 C1 S0**(每层独立、场即算即弃、**加性汇回**、不共享)。

### 5.3 实跑与结果(RS trial 1)

3×2 矩阵消融,结论(2026-10-16 判读):

- **全绿** = 五个单开旋钮 + AS 组合(A 链 + 共享);
- **全灭** = AC、ACS——**A 的相容性:配 S 无害,配 C 全灭**;
- **CS 半绿**(与 θ init=proj 交互);
- 星档 a0b0c1s0 = 单开 C 的加性汇回,唯一稳定打平/超过 baseline
  的配置族。(RS trial 1 粗筛终值表:03 §3;正式矩阵判读:03 §4
  ——rwi 批 96 run 排序表,hc/mHC 行即 sanity check 灰行。)

**这是全时间线最重要的消融结果之一**:乘性 gate 族(V2 时代的
ε-gate 遗产)在残差结构语言下被正式判死,加性汇回(C1)成为此后
全部主力档的标配。

### 5.4 段式预留(v1.4)

这批同期定型的工程语义:**tsv 表格的号段预留**(RESERVE_BASE 起
N 个号,基址按容器错开防兄弟容器双跑)——「热加行落预留号,不
重挂容器」。配套的 run 编号纪律:

> 「run id 每代重置……不然以后数字编到天上去了。」

每批的 run id 从头编,防重合靠代名(GEN)——这也是 03 各批 tsv
里 id 都是小编号的原因。

### 5.5 复盘

## 6. 时代 5:RWI 56 与 v5 100——支路初始化换轨与两星档定格(2026-10-16 → 10-24)

### 6.1 背景

到此为止,全部 WONN 档都遵守 **no-op 初始化纪律**(支路 W_out 零

权重从来不是零起步的。

### 6.2 rwi 拍板

**RWI = random weight initialization(随机权重初始化)**,语义:
「**主干怎么 init 支路就怎么 init**」——支路权重按主干的初始化
分布正常采样(w_out 走 scaled 档 N(0, 0.02/√96),w_delta/w_omega

参与。这是对 no-op 纪律的**有意放开**(不再保证起点与 baseline
一致——判读从「bit 一致起步分岔」变成「分布同族起步比较」)。

工程牵连:各档 ckpt 不能再从 backbone 底座硬链接,要**重新物化**
(prep_rwi 的 seed 重 init 构造路,04 §8);物化级判据换成 RWI 生
效读数(w_out 非全零 + std 量级 ±30% + rs_add_w == 1.0)。

### 6.3 lr 3e-4 热改判(rwi34 事件)

RWI 批(56 run)挂出后、跑的过程中,判读发现 1e-3 家族对 rwi 档
整体偏高(支路从第一步就参与 → 早期扰动大)。拍板:全族 lr 换
3e-4。问题:三片任务已在集群排队,代码包 pin 死不能动。解法 =
**物料热加载通道**(04 §6)带一个新 entry 进去——`rwi34` wrapper,
15 行核心:hydra 解析前剥掉 argv 里的 `optim.lr=1e-3`、尾部注入
`3e-4`。曲线语义 = 1e-3 家族纯 scale ×0.3(warmup/cosine 形状不变),
批内可比性保持。这个 wrapper 后来成为 RWI 系全部批次的标准 entry
(ts16 本地续跑时还因为漏配它出过一次 lr 换轨事故,见时代 8)。

### 6.4 v5 批 100 run 与两星档

RWI 语义 + lr 3e-4 + 两键化(供奉十五批:宿主形态 form 与挂载位点
gate 从单键拆成正交两键——「hc2 宿主 × swish 挂载」这类叠加档成

### 6.5 判读口径换代(table500 → w25 → w100)

v5 时代的判读反思催生了口径革命(三窗对比,2026-10-27 定稿):

## 7. 时代 6:HC 对照族、λ 轴、梯度审计与 phase_mean(2026-10-24 → 10-29)

### 7.1 背景

两星档定格后,下一步是「更上一层楼」。三条线并进:①容量/结构轴
(分组 G 与组间 λ);②HC/mHC sanity check 对照族的完整跑量;③一条
因为算子改造而起的工程质量线(梯度审计)。

### 7.2 HC/mHC:sanity check 对照族(与 WONN 正交,不可比)

**HC = HyperConnections**(残差流多流化,把单条残差流拆成 n 条
可学习混合的流)。引入目的不是与 WONN 竞争,而是 **sanity check
(合理性自检)**——它回答两个独立于 WONN 的问题:

1. **训练设定本身健康吗?**:HC 是文献里已知有效的架构改动。如果
   连它都不能在这个 toy model + toy dataset 的 setting 下降低
   loss,那说明我们的训练设定(数据/优化器/判读口径)本身有问题,
   一切 WONN 档的数字都不可信;
2. **增益的 order of magnitude(数量级)是多少?**:已知有效架构
   在同一设定下能降多少,给了 WONN 的效应量一个参照标尺——判读
   WONN 档的 −0.001 ~ −0.004 时,我们知道它处在「合理量级带」里,
   而不是异常值。

**sanity check 结果(双问全过)**:①HC/mHC 全族稳定降 loss——训练
设定健康;②已知架构的增益量级 ~ −0.004 ~ −0.006(hc2_n4 最深
−0.00635)——WONN 档的增益与它同数量级。数字(终态全表灰行):

| 档 | w100 | Δ |
|---|---|---|
| hc2_n4 | 0.93543 ± 0.00039 | **−0.00635** |
| hc_n4 | 0.93728 ± 0.00116 | −0.00450 |
| mhc2_n4 | 0.93772 ± 0.00028 | −0.00407 |
| hc_n5 | 0.93807 | −0.00372 |
| hc_n2 | 0.93815 | −0.00364 |
| hc_n3 | 0.93828 | −0.00350 |
| mhc_n2 | 0.94162 | −0.00017 |

(灰行族全量读数:03 §5 hc2 段(同窗 @4000)与 03 §4 rwi 批表
hc/mHC 行;ts16 B 类叠加档见 03 §11。)

**⚠️ 判读纪律(学长定调,2026-11-14)**:HC/mHC 与 WONN 是**正交
的两个东西,没有可比性**——HC 改的是残差流的组织方式(主干内部),
WONN 加的是振荡动力学侧支(主干外部);两者的参数量、作用位置、
机制都不同族,「HC 优于 WONN」或「WONN 优于 HC」式的比较都是误导。

不是排名。hc2/mhc2 宿主与 swish 挂载的**叠加档**(ts16 B 类)才是
两者关系的正确问法——正交组件能不能叠加出独立增益,而不是谁替代
谁。

### 7.3 λ 轴:g4 批 120 run 与两级构想的种子(49 档合表:03 §6;g16 分块表:03 §8)

**λ = 组间耦合**(分组 G>1 后,组与组之间的混合强度)。g4 批
(G=4,120 run)扫 λ 的参数化:

- `off`:组间零交互(块对角 c_ij,组完全独立);
- `static`:可学习标量 λ [G,G](对角 mask 永久零——「场的平均不
  自耦合」;Kuramoto 群间强度语义);
- `dynamic`:per-position λ(x)(内容相关的组间混合);
- form(mean_sin / sin_psi / phase_diff):组间平均场的合成方式
  (sin_psi 用组内相位圆均值 ψ=atan2(s̄,c̄)——在圆周上做平均的
  正确方式)。

学长在这条轴上给了关键的结构洞察(两级构想的种子,原话供奉):

## 8. 时代 7:group8 与速度线——两级层级落地、kernel 提速与「过不了线」(2026-10-29 → 11-05)

### 8.1 背景

时代 6 的「static λ 就是更高层级的 c_ij」洞察落地:**group8 批
48 run**——两级分组(m·G1·G2 层级:小组 8 振子 × G1 小组 × G2
大组),λ1 [G2,G1,G1] 管小组间、λ2 [G2,G2] 管大组间,mask 同款
对角归零。form 用 sin_psi 两级折叠(小组圆均值 ψ1 → 大组圆均值
ψ2)。同期,算子加速线进入攻坚(WONN 侧支的 wall clock 开销要压
到主线可接受——**判读线 = 增量 ≤ 5%**,超线则结构再好也白搭)。

### 8.2 group8 结果

两级四档(op/noop × m4/m8 的组合):

| 档 | w100 | Δ |
|---|---|---|
| 2l32x8_sinpsi_pnoff_m4_lambda_noop | 0.94069 ± 0.00058 | −0.00110 |
| 2l16x8_sinpsi_pnoff_m8_lambda_op | 0.94102 ± 0.00085 | −0.00077 |
| 2l32x8_sinpsi_pnoff_m4_lambda_op | 0.94104 ± 0.00073 | −0.00074 |
| 2l16x8_sinpsi_pnoff_m8_lambda_noop | 0.94140 ± 0.00113 | −0.00039 |

(「2l」= 两个 λ 层级;op/noop = λ 初始化 op 档/零起步档。)四档
全部稳定打平或小胜 baseline,但**两级 vs 单级的增益没有拉开**——
两级结构的复杂度投资回报为正但边际(36 行合表全量:03 §9)。
这条结论后来被时代 8 的 Ω换轨修正重新解释(见 9.3:group8 全族的 Ω 供给是 per_layer,跨层
接力链缺席——结构轴的潜力可能被发动机缺陷压住了)。

容量轴对照(同一判读窗):V256(单组加宽)+0.0008 → g4m128
+0.014 → g256_m4 +0.054~0.081 大炸——**分组不是免费的容量轴**,
组数把 c_ij 的组内秩挤小,极端分组(g256)直接破坏表达。

### 8.3 速度线(profiler 驱动的三段攻坚)

侧支增量从 +122.9ms/步起查,三段攻坚(细节按档案体例从简,只讲
发现与结果):

1. **r99 profiler**:增量 97% 是 **CPU launch 开销**(kernel 调度
   等待,GPU 两实现同速)——不是 GPU compute bound。这条发现把
   优化方向从「算得快」转向「launch 得少」;
2. **sincos_sum grid over-decomposition 修复**:一个融合 kernel
   把 209 万个 micro-program(过度细分的并行块)派发出去,单步
   460.7ms——tiled 重写(合理的块划分)后 15.5ms,**29.7×**;
3. **CUDA graph 实装**:把整段 kernel 序列录制成图重放,launch
   开销增量砍 74%(+122.9 → +31.5ms/步)——但 +19.2% 总增量
   **仍 FAIL 5% 线**。残量构成:in-graph launch 地板(1.8μs/节点)
   + T 步链的顺序依赖(相位递推不可并行)。

**MFU(model FLOPs utilization,实际算力利用率)三口径**:
11.3%(含全部侧支开销)/ 38%(纯主干理论窗)/ 4.04%(全模型
端到端)——toy 平台本身离 GPU 峰值很远(小模型 + 小 batch 的
天然低利用率),侧支的 5% 线是**相对**增量线不是绝对利用率线。

4. **mini_it**:本机双卡的迷你迭代验证环境(三 phase:装配/
    smoke/对拍)——速度线的改动全部先过它再上集群。

### 8.4 复盘

- group8 的「边际增益」判读是个**被污染的判读**(时代 8 揭晓):
  两级结构是在 per_layer Ω 上验证的,发动机缺件下的结构评估——
  这不是白跑(两级语义本身被验证无害且小正),但它提醒:**结构
  轴与发动机轴的交互可能掩盖结构潜力**;
- 速度线的教训:profiler 先行(r99)避免了在错误方向上优化 GPU
  kernel——如果直接去优化 sincos_sum 的算术,永远发现不了问题是
  launch 侧的;
- 「过不了 5% 线」的诚实结论被完整保留:**结构增益(−0.001 ~
  −0.003)与算力开销(+19.2%)的性价比问题在 toy 平台上没有解**,
  这是留给未来(更大模型上侧支占比自然摊薄)的开放问题。

### 10.2 方法论沉淀(全时间线的可迁移资产)

1. **单变量纪律**:一切跨档比较必须单变量(Ω 事件的教训——
   双变量混淆让数周的结论作废);复用配置 = 全键 diff 对拍;
2. **对照臂族**:baseline + ffnmatch(容量对照)+ no-op 检查
   (起点一致)——三件套判读任何「增益」;
3. **完整退火 + w100 + done 门控**:判读窗本身是实验设计;
4. **原话供奉**:决策以原话粒度留档(「记这个未来我才看得懂」);
5. **手推导数必须 autograd 数值验证**(判据族四件:尺度放大 /
   rel / 通路隔离 / T-sweep);
6. **发散是信号**:ε-gate 的发散催生了整条 mid-flight decay
   支线——负面结果驱动设计;
7. **物化而非手搓**:全部 ckpt 从底座 prep 脚本构造,可重生(
   清理轮的资源红利);
8. **profiler 先行**:优化方向由数据定(launch vs compute 的
   97% 发现),不由直觉定。
